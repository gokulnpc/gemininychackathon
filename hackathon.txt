Hey builders! 🛑 Stop typing, and start interacting! We are moving beyond the text box. The future isn't about just chatting with AI—it's about immersive, real-time experiences. To celebrate the power of multimodal AI, we’re challenging you to build the next generation of agents that can help you see 🙈, hear 🙉, speak 🙊, and create in the Gemini Live Agent Challenge.

REQUIREMENTS
WHAT TO BUILD

Entrants must develop a NEW next-generation AI Agent that utilizes multimodal inputs and outputs and moves beyond simple text-in/text-out interactions. Projects should leverage Google’s Live API with the creative power of video/image generation to solve complex problems or create entirely new user experiences within one of these three categories: 

Live Agents 🗣️

Focus: Real-time Interaction (Audio/Vision).

Build an agent that users can talk to naturally can be interrupted. This could be a real-time translator, a vision-enabled customized tutor that "sees" your homework, or a customer support voice agent that handles interruptions gracefully.

Mandatory Tech: Must use Gemini Live API or  the use of ADK. The agents are hosted on Google Cloud.

Creative Storyteller ✍️

Focus: Multimodal Storytelling with Interleaved Output

Build an agent that thinks and creates like a creative director, seamlessly weaving together text, images, audio, and video in a single, fluid output stream. Leverage Gemini's native interleaved output to generate rich, mixed-media responses that combine narration with visuals, explanations with generated imagery, or storyboards with voiceover, all in one cohesive flow. Examples include Interactive storybooks (text + generated illustrations inline),  marketing asset generator (copy + visuals + video in one go), educational explainers (narration woven with diagrams), and social content creator (caption + image + hashtags together).

Mandatory Tech: Must use Gemini's interleaved/mixed output capabilities. The agents are hosted on Google Cloud.

UI Navigator ☸️

Focus: Visual UI Understanding & Interaction

Build an agent that becomes the user's hands on screen. The agent observes the browser or device display, interprets visual elements with or without relying on APIs or DOM access, and performs actions based on user intent. Examples include a universal web navigator, a cross-application workflow automator, or a visual QA testing agent.

Mandatory Tech: Must use Gemini multimodal to interpret screenshots/screen recordings and output executable actions. The agents are hosted on Google Cloud.

 

All projects MUST: 

Leverage a Gemini model

Agents must be built using either Google GenAI SDK OR ADK (Agent Development Kit)

Use at least one Google Cloud service

# Gemini Hackathon AI Video Editor Plan

## Summary

Build the product as a **real-time AI-assisted video editor** with **Live Agents** as the primary submission track, while deliberately incorporating the other two tracks as supporting differentiators:

- **Primary track: Live Agents**
  - real-time voice/text editing copilot
  - interruption-friendly conversation
  - live timeline updates and guided confirmations
- **Secondary differentiator: Creative Storyteller**
  - interleaved output for storyboards, captions, visual concepts, hooks, overlays, and creative directions
- **Secondary differentiator: UI Navigator**
  - screen-aware editor assistance that can interpret the current canvas/timeline/sidebar state and act on it

This gives you both:
- a strong **hackathon narrative** for Gemini/Google
- a credible **soft-launch product architecture** for an AI-assisted editor

The product pitch becomes:
**“A live Gemini-powered video editor that listens, sees the current edit, proposes creative changes in mixed media, and applies confirmed edits directly to the timeline.”**

## Product Positioning

- Submission angle
  - Present this as a **Live Agent for video editing**, not just a chatbot attached to an editor
  - The key novelty is that the agent can:
    - hear user intent
    - inspect current project state
    - understand the visual editor context
    - generate creative assets/previews
    - apply confirmed edits to the timeline in-session

- How the 3 hackathon tracks map into one product
  - **Live Agents**
    - Gemini Live API voice session
    - interruptible assistant during editing
    - low-latency responses and live stateful editing
  - **Creative Storyteller**
    - Gemini interleaved output for:
      - creative direction
      - storyboard beats
      - hook/title concepts
      - generated visual previews
      - caption/theme suggestions
      - music/mood recommendations
  - **UI Navigator**
    - agent consumes screenshot/editor-state context
    - understands selected clip, playhead region, visible timeline and canvas
    - outputs executable editor actions rather than plain chat responses

- Soft-launch framing
  - v1 is not “fully autonomous editor”
  - v1 is a **creative copilot with controlled execution**
  - user stays in charge; agent is fast, multimodal, and useful immediately

## Key Changes

- Treat the AI assistant as the main product system
  - Editor SDK is an implementation detail
  - Twick remains the fastest v1 shell because your repo already uses Twick-shaped project JSON
  - all agent behavior must go through a vendor-neutral edit-command layer so you can replace Twick later

- Add a **Hackathon Capability Layer** with 3 explicit modes
  - **Live Edit Mode**
    - voice/text conversation with Gemini Live
    - interruption support
    - current-project awareness
    - apply edits after confirmation
  - **Creative Mode**
    - interleaved text + generated image/audio preview output
    - examples:
      - “give me 3 horror opening concepts”
      - “show a new thumbnail direction”
      - “generate title card ideas and matching captions”
  - **Screen-Aware Mode**
    - agent reads screenshot or current editor snapshot
    - identifies active element/track/region
    - recommends or applies localized changes like:
      - “move this title up”
      - “trim this overlay”
      - “replace the music here”
      - “make the first 3 seconds more punchy”

- Expand the current narrow edit agent into a true editing assistant
  - today it mainly patches caption style/music and some preview flow
  - target v1 support:
    - add/edit/remove text overlays
    - caption add/change/theme operations
    - add image overlays / stickers / emoji
    - add/swap music and sound mood
    - apply basic effects/transitions
    - timing adjustments for supported elements
    - add opening hook/title card
    - scene-level enhancement suggestions

- Add a structured **Edit Command Engine**
  - agent returns normalized commands, not Twick-specific mutations
  - each command is validated, previewable, reversible, and projectable into `project_json`
  - representative commands:
    - `add_text_overlay`
    - `update_caption_style`
    - `insert_visual_asset`
    - `replace_music`
    - `apply_effect`
    - `trim_element`
    - `move_element`
    - `delete_element`
    - `add_hook_title`

- Add confirmation and safety as core UX
  - selected default remains **suggest + confirm**
  - no destructive edit without confirmation
  - no large multi-step batch change without a short plan summary
  - user can accept, reject, refine, or undo

## Test Plan

    - “Make this caption more vibrant”
    - “Swap this image with something darker”
    - agent applies targeted edits to the correct element

- Backend tests
  - multimodal request context -> structured command plan

  - screenshot-assisted requests map to safe supported commands
  - patched timeline remains valid Twick-compatible JSON

- Frontend tests
  - live session UI handles transcript, tool, preview, confirm, and apply events
  - editor context capture is included in agent calls
  - applied command results update the timeline immediately
  - export persists latest confirmed timeline and triggers one backend render

## Assumptions

- Primary hackathon track is **Live Agents**

- The most important reusable abstraction is the **vendor-neutral edit command model**
- The product should be judged and demoed as one cohesive multimodal system, not three disconnected hackathon features
